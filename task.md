# Техническое задание на разработку серверной части онлайн-магазина «ShopOnline»

## 1. Общие сведения

### 1.1. Наименование проекта
Серверная часть (backend) онлайн-магазина «ShopOnline».

### 1.2. Заказчик
Компания «ShopOnline».

### 1.3. Цель разработки
Создание серверного приложения, предоставляющего REST API для управления товарами и категориями, расчёта стоимости товаров, загрузки изображений и обеспечения взаимодействия между клиентами/персоналом и базой данных магазина.

### 1.4. Область применения
Серверная часть используется как основа для работы онлайн-магазина: витрины товаров, административной панели, интеграций с клиентскими приложениями.

---

## 2. Требования к функциональности

Сервер должен реализовывать REST API со следующими возможностями:

### 2.1. Управление товарами (CRUD)
- Создание товара.
- Получение списка товаров с фильтрацией и пагинацией.
- Получение информации о конкретном товаре.
- Частичное обновление информации о товаре.
- Удаление товара.

### 2.2. Управление категориями
- Получение списка категорий товаров.

### 2.3. Специальные выборки
- Получение списка дисконтных товаров.
- Получение списка товаров по категории.
- Получение общей стоимости всех товаров.

### 2.4. Работа с изображениями
- Приём изображений товаров в формате base64.
- Сохранение изображений на сервере в папке `./image`.

---

## 3. Технические требования

### 3.1. Язык программирования и среда
- **Язык:** Node.js (JavaScript).
- **Сервер:** встроенный модуль `http` или `https` Node.js (без использования сторонних веб-фреймворков, если не согласовано отдельно).
- **СУБД:** PostgreSQL.

### 3.2. Хранение данных
- Товары и категории хранятся в PostgreSQL.
- Структура данных должна соответствовать предоставленным JSON-файлам `db_goods.json` и `db_category.json` (поля: `id`, `title`, `price`, `description`, `category`, `discount`, `count`, `units`, `image`).
- Необходимо предусмотреть миграцию/инициализацию БД начальными данными из указанных JSON-файлов.

### 3.3. Обработка изображений
- Изображения принимаются в формате base64 (например, в поле `image` при создании/обновлении товара).
- Декодированные файлы сохраняются в каталог `./image`.
- Имя файла формируется на основе идентификатора товара (например, `<id>.jpg`).
- В БД сохраняется относительный путь к изображению.

### 3.4. Обработка ошибок и валидация
- Валидация входных данных (обязательные поля, типы, диапазоны значений, корректность base64).
- Возврат корректных HTTP-статусов:
  - `200` — успешный запрос;
  - `201` — ресурс создан;
  - `400` — неверный запрос / ошибка валидации;
  - `404` — ресурс не найден;
  - `500` — внутренняя ошибка сервера.
- Единый формат ответа об ошибке (например, `{ "error": "описание" }`).

### 3.5. CORS
- Включить поддержку Cross-Origin Resource Sharing для доступа к API из разных источников (заголовки `Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, обработка `OPTIONS`-запросов).

### 3.6. Установка и запуск
- Проект должен устанавливаться и запускаться командой `npm start`.
- В репозитории должен присутствовать файл `README.md` с инструкциями по установке, настройке БД и запуску сервера.
- Должен быть файл `package.json` со скриптом `start` и описанием зависимостей.

### 3.7. Развёртывание
- Сервер должен быть доступен по IP-адресу или доменному имени.
- Допускается использование платного или бесплатного хостинга.

## 4. Спецификация API

Базовый префикс: `/api`.

### 4.1. Товары

#### `GET /api/goods`
Получение списка товаров.

**Query-параметры:**
- `search` — строка поиска (по названию/описанию);
- `page` — номер страницы для пагинации (целое число ≥ 1).

**Ответ:** `200 OK`, массив товаров.

---

#### `POST /api/goods`
Создание нового товара.

**Тело запроса (JSON):**
```json
{
  "title": "string",
  "price": 0,
  "description": "string",
  "category": "string",
  "discount": 0,
  "count": 0,
  "units": "string",
  "image": "base64-строка"
}
